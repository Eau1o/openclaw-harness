# 设计决策

## 核心原则

1. **边界即契约**：外部数据在边界处解析形状，领域模型保持内部一致
2. **知识自包含**：所有信息版本化存储在仓库，支持 diff/lint
3. **可读性优先**：代码优先为智能体优化，清晰度 > 简洁
4. **单向依赖**：Types → Config → Repo → Service → Runtime

## 决策记录

### 2026-04-09 采用纯文件记忆系统
- **原因**：可版本控制、可 diff、可 lint
- **替代方案**：向量数据库（否决，增加复杂度）
- **结论**：使用 Markdown 文件 + memory_search

### 2026-04-10 Token 刷新机制
- **已实现**：基础 Token 刷新
- **待补充**：刷新令牌轮换策略（TD-002）

## 架构约束

| 约束 | 说明 |
|------|------|
| 无循环依赖 | 模块间禁止循环引用 |
| 接口隔离 | 依赖抽象而非实现 |
| 单一职责 | 每个模块专注一件事 |

## 技术选型

| 场景 | 选型 | 原因 |
|------|------|------|
| 记忆存储 | Markdown 文件 | 版本控制、diff |
| 配置管理 | 环境变量 | 12-Factor App |
| 日志 | Providers 接口 | 横切关注点统一 |
