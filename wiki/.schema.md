# Wiki Schema — 机器可读规范

> 本文件是 LLM 维护 wiki 时的精确指令集。
> 与 `WIKI.md` 共同生效，WIKI.md 提供高层意图，本文件提供执行细节。

---

## 文件命名规则

```
entity/     → {lowercase-kebab-case}.md
concept/    → {lowercase-kebab-case}.md
source/     → {original-name-or-slug}.md
synthesis/  → {descriptive-title}.md
```

**强制：**
- 空格用 `-` 替代
- 中文内容全拼拼音（避免 Unicode 问题）
- 唯一性：同目录内不可重名

---

## frontmatter 必填字段

### entity/
```yaml
title: string          # 显示名称
tags: [string]         # 标签
created: YYYY-MM-DD
updated: YYYY-MM-DD
aliases: [string]      # 别名，用于搜索命中
```

### concept/
```yaml
title: string
tags: [string]
created: YYYY-MM-DD
updated: YYYY-MM-DD
related: [string]      # 相关 concept wikilink 列表
```

### source/
```yaml
title: string
tags: [string]
sourcePath: string     # 相对 wiki/sources/ 的路径
ingestDate: YYYY-MM-DD
type: article|paper|book|video|podcast|conversation
```

### synthesis/
```yaml
title: string
tags: [string]
created: YYYY-MM-DD
updated: YYYY-MM-DD
derivedFrom: [string]  # 来源页面列表
```

## 内容写作规范

### 段落结构
- 每段不超过 5 句
- 超过 3 个要点用列表
- 结论前置（倒金字塔）

### 引用格式
- 来自 source 的直接引用：
  ```markdown
  > "[原文摘录]"
  > — [[source/document-name]]，p.XX
  ```
- wikilink 引用：`[[entity/page-name]]`

### 矛盾处理
当新 source 与旧 claim 冲突时：
```markdown
> [!conflict] 矛盾标记
> 旧说法：...[旧 claim]
> 新来源：[[source/new-document]]（YYYY-MM-DD）
> 状态：[未解决/已验证/已修正]
```

### 未完成标记
```markdown
> [!todo]
> - [ ] 待核实：具体问题描述
> - [ ] 待补充：缺失信息
```

## 来源同步规范（Git Repo 增量更新）

### 多仓库支持
`wiki/sources/github/` 下每个目录是一个独立 git 仓库：
```
wiki/sources/github/
├── openclaw/           → 输出到 wiki/pages/source/github-openclaw/
│   └── docs/           ← ingest 时使用这个目录
├── some-other-repo/    → 输出到 wiki/pages/source/github-some-other-repo/
└── another-project/   → 输出到 wiki/pages/source/github-another-project/
```
命名规则：`{dir-name}` → 输出到 `github-{dir-name}/`

> [!note]
> sources/ 不再是原始文件的镜像副本，而是 git 仓库本身。
> ingest 从 git 仓库的子目录（如 docs/）读取，不复制文件到别处。

### 同步状态记录
在 `wiki/.sync-state.json` 中记录每个仓库的同步状态：
```json
{
  "repos": {
    "github-openclaw": {
      "repoPath": "wiki/sources/github/openclaw",
      "sourceDir": "docs",
      "lastCommit": "abc123...",
      "lastSync": "2026-04-13T16:30:00+08:00",
      "outputDir": "wiki/pages/source/github-openclaw"
    }
  }
}
```

### 增量同步流程
```
1. 扫描 wiki/sources/github/ 下所有含 .git 的目录
2. 对每个仓库执行 git fetch && git rev-parse HEAD
3. 对比 lastCommit，有变化则：
   - 重新 ingest 该仓库的 sourceDir（如 docs/）到 outputDir
   - 更新 .sync-state.json 的 lastCommit 和 lastSync
4. 报告同步结果（新增/更新页面数）
```

### 非 Git 来源
书籍、文章、论文等非 git 来源：
```
wiki/sources/
├── books/              # 放置 .md 文件
├── articles/           # 放置文章 .md 文件
└── papers/            # 放置论文 .md 文件
```
通过 `wiki-ingest` skill 手动处理，不走批量同步流程。

## Ingest 详细流程

### Step 1：预处理
```
1. 确认 source 文件存在且可读
2. 如果是 URL，用 web_fetch 抓取内容
3. 如果是 PDF/Word，提取文本（尽可能）
4. 生成 source slug：建议 `yyyy-mmdd-{slug}` 格式
```

### Step 2：分析
```
1. 识别 document type（article/paper/book/...）
2. 提取：标题、作者、日期、核心论点
3. 识别：提及的实体、概念、关系
4. 标记：与现有 wiki 的潜在关联
```

### Step 3：写入
```
1. 在 source/ 创建新页面
2. 检查 entity/ 和 concept/ 是否需要新建或更新
3. 更新 _index.md
4. 追加 log.md
```

### Step 4：报告
```
输出 JSON 格式报告：
{
  "action": "ingest",
  "source": "...",
  "pagesCreated": [...],
  "pagesUpdated": [...],
  "conflicts": [...],
  "todos": [...]
}
```

## Query 详细流程

### Step 1：定位
```
1. 读取 _index.md
2. 提取相关分类下的页面列表
3. 如有关键词，用 grep 全文搜索 pages/
```

### Step 2：读取
```
1. 读取所有命中的页面（上限 10 个）
2. 提取与 query 最相关的段落
3. 识别 [[wikilink]] 引用的上下文
```

### Step 3：综合
```
1. 整合所有来源，给出完整回答
2. 标注参考：`[参考：[[source/...]]]`
3. 如有矛盾，明确指出
4. 结尾问用户是否写回 wiki
```

## Lint 检查清单

### A. 连通性
- [ ] 所有 [[wikilink]] 都指向存在的页面
- [ ] 所有 entity/ 页面都有 inbound links（无孤儿）
- [ ] 所有 concept/ 页面都有 inbound links（无孤儿）

### B. 时效性
- [ ] 检查 source 的发布时间，不早于 5 年
- [ ] 标记 "待核实" 超过 30 天未处理的条目
- [ ] frontmatter `updated` 与实际修改时间一致

### C. 一致性
- [ ] 同一实体在不同页面的描述是否一致
- [ ] 矛盾标记是否已解决或推进
- [ ] tags 是否符合规范（无冗余、无拼写错误）

### D. 完整性
- [ ] index.md 是否与实际 pages/ 一致
- [ ] 是否有 concept 应该被创建但缺失
- [ ] 重要引用是否有对应的 source/ 页面

## 快速命令

```bash
# 统计页面数量
find wiki/pages -name "*.md" | wc -l

# 查找孤儿页面（无 inbound link）
# 需要配合 grep 和人工判断

# 搜索关键词
grep -r "关键词" wiki/pages/

# 查看最近更新
grep "^updated:" wiki/pages/**/*.md | sort -t: -k3
```
