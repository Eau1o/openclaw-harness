# wiki-query — 查询 Wiki 知识库

## 功能描述

针对 wiki 知识库提问，LLM 搜索相关页面并综合回答。
核心原则：**优秀回答应写回 wiki 作为新页面**，让知识持续积累。

## 触发方式

用户提问且 wiki 中已有相关内容时自动激活。
用户明确说"查一下 wiki"、"从知识库回答"时激活。

## 必要参数

| 参数 | 来源 | 说明 |
|------|------|------|
| `question` | 用户消息 | 要回答的问题 |

## 可选参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `scope` | all | 查询范围：all / entity / concept / source / synthesis |
| `maxPages` | 10 | 最多读取多少个页面 |
| `writeBack` | ask | 是否写回 wiki：ask / always / never |

## 执行流程

### Step 1：定位相关页面

```
1. 读取 wiki/pages/_index.md
2. 根据 question 关键词匹配分类
3. 如果关键词明确，直接 grep 搜索 pages/
4. 收集候选页面列表（上限 maxPages）
```

### Step 2：读取并提取

```
1. 依次读取候选页面的 frontmatter 和正文
2. 提取与 question 最相关的段落
3. 追踪 [[wikilink]] 引用，获取更多上下文
4. 识别矛盾点和信息空白
```

### Step 3：综合回答

```
1. 整合所有来源，给出完整回答
2. 格式选择（根据问题类型）：
   - 解释性 → 叙述 + wikilink
   - 对比性 → 表格
   - 操作性 → 步骤列表
   - 分析性 → 段落 + 引用
3. 标注参考：每个要点附上 [[source/...]] 引用
4. 明确标注不确定的信息
5. 识别并标注潜在的矛盾
```

### Step 4：写回建议

```
1. 评估回答价值：
   - 是否包含新洞察？→ 建议写回
   - 是否综合了多个页面？→ 强烈建议写回
   - 是否纠正了旧错误？→ 必须写回
2. 如果建议写回：
   - 先展示回答
   - 结尾询问：要不要把这个写回 wiki 作为 [[synthesis/xxx]]？
3. 如果用户同意：
   - 创建 synthesis/ 页面
   - 更新 _index.md
   - 追加 log.md
```

### Step 5：输出格式

```markdown
## 查询结果

**问题**：[用户问题]

---

[综合回答]

---

**参考页面**：
- [[entity/xxx]]
- [[concept/yyy]]
- [[source/zzz]]

**置信度**：高 / 中 / 低（存在未核实信息）

---
💡 这个回答有价值，我可以把它写回 wiki 作为综合分析页。要不要？
```

## 特殊情况处理

### 1. 找不到相关内容

```markdown
## 查询结果

**问题**：[用户问题]

在当前 wiki 中未找到直接相关的页面。

**可能的方向**：
- "XXX" 相关的 entity 页面尚不存在
- "YYY" 概念还未被摄入

---
要不要我先摄入相关的来源？
```

### 2. 存在矛盾信息

```markdown
## 查询结果

**问题**：[用户问题]

找到两个页面对同一问题的说法不一致：

| 来源 | 说法 |
|------|------|
| [[source/aaa]] | A 观点 |
| [[source/bbb]] | B 观点 |

> [!conflict]
> 需要进一步核实。当前倾向于 [选择]。

**建议**：进行一次 wiki-lint 来系统性解决这个矛盾。
```

### 3. 回答涉及多个不相关主题

```markdown
## 查询结果

**问题**：[用户问题]

这个问题涉及多个独立主题：

### 主题 1：XXX
[简短回答]（[[entity/xxx]]）

### 主题 2：YYY
[简短回答]（[[concept/yyy]]）

---
这是一个宽泛问题，具体想了解哪个方面？
```

## 错误处理

| 错误类型 | 处理方式 |
|----------|----------|
| _index.md 不存在 | 提示 wiki 未初始化，建议先摄入来源 |
| 页面读取失败 | 跳过该页面，从其他页面回答 |
| 超时 | 返回已收集的部分回答，标注不完整 |

## 注意事项

1. **wikilink 必须准确**——指向存在的页面
2. **不要编造信息**——wiki 中没有的标注"待核实"
3. **每次回答都是潜在的合成页**——评估是否值得写回
4. **引用要完整**——方便用户追溯原始来源

## 依赖 Skill

- `obsidian` — 可选，用于在 Obsidian 中打开相关页面
- `wiki-lint` — 当发现矛盾时建议触发
